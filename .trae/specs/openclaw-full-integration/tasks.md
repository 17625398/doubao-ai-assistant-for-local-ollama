# OpenClaw 全面集成融合 - 实施计划

## [ ] 任务 1：完成 OpenClaw 运行时接入基线
- **优先级**：P0
- **依赖**：无
- **描述**：
  - 梳理本项目与 OpenClaw 的集成边界，明确 `@doubao/core`、`@doubao/web`、浏览器扩展与本地服务层职责
  - 统一 `openclaw` CLI、Gateway、本地配置文件、日志目录、工作区目录的访问入口
  - 为后续 Gateway、渠道、技能、浏览器和节点能力建立公共类型与服务抽象
- **验收标准**：AC-1, AC-12
- **测试需求**：
  - `human-judgment` TR-1.1：确认模块职责划分清晰，后续功能有明确落位
  - `programmatic` TR-1.2：能够正确识别本机是否存在 `openclaw` CLI 与基础运行环境
- **注意**：Windows 场景优先按 WSL2 路径设计，不直接假设原生环境完全可用

## [ ] 任务 2：实现 Gateway 生命周期与健康检查
- **优先级**：P0
- **依赖**：任务 1
- **描述**：
  - 实现 Gateway 状态检测、启动、停止、重启和自动重连
  - 打通 `doctor`、健康检查、版本读取、认证模式识别和端口配置展示
  - 把 Gateway 关键事件接入本项目状态中心与错误提示系统
- **验收标准**：AC-1, AC-9
- **测试需求**：
  - `programmatic` TR-2.1：Gateway 启停和健康检查结果可被稳定读取
  - `programmatic` TR-2.2：Gateway 不可用时能返回结构化错误
  - `human-judgment` TR-2.3：状态展示和恢复提示清晰可理解
- **注意**：需覆盖 Gateway 未启动、端口不可达、认证失败和配置损坏等场景

## [ ] 任务 3：实现 OpenClaw 安装与首次引导流程
- **优先级**：P0
- **依赖**：任务 1, 任务 2
- **描述**：
  - 设计 OpenClaw 首次接入向导，覆盖 Node 版本、CLI 安装、`onboard`、模型配置和渠道准备
  - 输出平台差异化提示，包括 Windows WSL2、macOS 权限和 Linux 依赖说明
  - 为常见失败场景提供一键复制命令和排错指引
- **验收标准**：AC-2, AC-12
- **测试需求**：
  - `human-judgment` TR-3.1：首次接入流程对新用户足够清晰
  - `programmatic` TR-3.2：环境校验结果能够正确反映实际状态
- **注意**：引导流程应尽量减少用户手工编辑配置文件

## [ ] 任务 4：实现配置管理与安全默认值
- **优先级**：P0
- **依赖**：任务 1, 任务 2
- **描述**：
  - 读取、展示并更新 OpenClaw 配置，覆盖模型、workspace、channels、browser、sandbox、auth、tailscale、voice、nodes
  - 建立配置校验机制与敏感项保护策略
  - 默认启用安全推荐值，突出 DM pairing、allowlist、非主会话沙箱和远程暴露风险
- **验收标准**：AC-3, AC-10, AC-11
- **测试需求**：
  - `programmatic` TR-4.1：配置变更后能正确保存并生效
  - `programmatic` TR-4.2：高风险配置会触发提示或拦截
  - `human-judgment` TR-4.3：配置界面层次清晰，用户能理解风险差异
- **注意**：避免把敏感令牌直接暴露在普通日志和 UI 列表中

## [ ] 任务 5：实现多渠道接入与认证管理
- **优先级**：P0
- **依赖**：任务 2, 任务 3, 任务 4
- **描述**：
  - 接入 OpenClaw 渠道列表和渠道状态，支持启用、禁用、连接测试和最近状态展示
  - 提供 `channels login`、二维码/Token/凭据类登录引导和失败提示
  - 支持展示 allowlist、DM policy、群组策略和渠道级别配置
- **验收标准**：AC-3, AC-10
- **测试需求**：
  - `programmatic` TR-5.1：至少一个渠道能够完成登录并在 UI 中显示可用状态
  - `programmatic` TR-5.2：渠道配置错误时能返回明确诊断结果
  - `human-judgment` TR-5.3：渠道管理界面便于查看状态与修复问题
- **注意**：优先支持 WebChat、Telegram、Discord、Slack、WeChat/Feishu 等项目价值较高的渠道

## [ ] 任务 6：实现消息路由、会话映射与多 Agent 绑定
- **优先级**：P0
- **依赖**：任务 5
- **描述**：
  - 将 OpenClaw 入站/出站消息映射到本项目统一消息模型
  - 按渠道、联系人、群组、线程和工作区建立会话映射
  - 支持为不同来源绑定不同 Agent，并隔离上下文、路由规则和会话状态
- **验收标准**：AC-4, AC-5
- **测试需求**：
  - `programmatic` TR-6.1：入站消息能稳定落入正确会话
  - `programmatic` TR-6.2：不同 Agent 的上下文不会串扰
  - `human-judgment` TR-6.3：会话与路由展示清楚，用户能理解消息去向
- **注意**：需兼顾私聊、群聊、reply-back 和跨会话转发场景

## [ ] 任务 7：完成知识库与记忆系统融合
- **优先级**：P1
- **依赖**：任务 6
- **描述**：
  - 将本项目知识库检索能力接入 OpenClaw 会话处理链路
  - 把渠道消息、会话摘要、技能执行结果和用户偏好写入本项目记忆系统
  - 提供按 Agent、会话、渠道维度的知识和记忆回溯能力
- **验收标准**：AC-6
- **测试需求**：
  - `programmatic` TR-7.1：知识检索结果能参与回答生成或辅助展示
  - `programmatic` TR-7.2：记忆写入和检索具备基本正确性
  - `human-judgment` TR-7.3：用户能在 UI 中理解知识引用和记忆来源
- **注意**：需要避免本项目记忆机制与 OpenClaw 原生会话压缩逻辑发生冲突

## [ ] 任务 8：实现 Skills、Workspace 与工具执行管理
- **优先级**：P1
- **依赖**：任务 4, 任务 6
- **描述**：
  - 展示 OpenClaw workspace、prompt 文件和技能目录结构
  - 支持技能来源识别、技能启停、技能安装、参数填写和执行结果展示
  - 预留 ClawHub 或技能发现入口，并补充权限说明
- **验收标准**：AC-7
- **测试需求**：
  - `programmatic` TR-8.1：技能列表和启停状态与实际 workspace 一致
  - `programmatic` TR-8.2：工具执行结果能够结构化返回并显示
  - `human-judgment` TR-8.3：技能管理界面足够直观，用户能理解工具用途
- **注意**：技能安装前应提示来源、风险和对工作区的影响

- **优先级**：P1

  - 落实 `oh-my-browser` 插件的安装、授权检查、桥接状态和错误恢复路径
- **验收标准**：AC-8
- **测试需求**：

  - `programmatic` TR-9.2：授权缺失、CLI 缺失、桥接失败时返回统一提示

## [ ] 任务 10：实现事件中心、日志中心与调试工具
- **优先级**：P1
- **依赖**：任务 2, 任务 5, 任务 6, 任务 8, 任务 9
- **描述**：
  - 统一接入 Gateway 事件流、渠道状态变化、技能执行状态和浏览器操作日志
  - 提供最近事件列表、日志筛选、错误分类、诊断摘要和导出能力
  - 为关键失败场景提供建议动作与快速重试入口
- **验收标准**：AC-9
- **测试需求**：

## [ ] 任务 11：实现远程 Gateway、Tailscale/SSH 模式支持
- **优先级**：P2
- **依赖**：任务 2, 任务 4, 任务 10

  - `human-judgment` TR-11.2：限制与安全提示完整、明确
